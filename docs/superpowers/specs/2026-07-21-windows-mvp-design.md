# Karma Windows MVP 设计规格

日期：2026-07-21  
状态：待用户审阅  
目标平台：Windows 10 22H2、Windows 11  

## 1. 目标

Karma Windows MVP 是一套面向家庭家长控制的本地内容防护软件。它在用户明确授权后监控全部活动显示器，以本地 ONNX 图像模型、OCR 色情关键词和连续帧状态共同评估风险，在高风险内容出现后遮罩并关闭可可靠归属的来源应用。

MVP 同时提供管理员密码、应用黑白名单、每周时间表、审计日志、Windows Service 常驻以及 Agent 自动恢复。默认不上传或保存屏幕帧、OCR 原文、完整 URL 和用户输入。

## 2. 非目标与安全边界

MVP 不实现以下能力：

- 不隐藏进程、文件或驱动，不使用 rootkit 技术。
- 不绕过 UAC、安全桌面、DRM、Windows 隐私提示或安全软件。
- 不安装自签根证书，不解密 HTTPS，不注入浏览器或其他进程。
- 不使用 ELAM、PPL 或内核驱动作为 MVP 的自保护机制。
- 不承诺抵御掌握本机管理员凭据、恢复环境或物理设备控制权的用户。
- 不把 macOS 实现纳入本期；共享协议避免不必要的平台绑定，为后续适配留出边界。

保护等级分为：

1. **强保护**：父母独占管理员凭据，孩子使用标准账户。普通用户不能停止服务、修改受保护配置或卸载组件。
2. **兼容保护**：孩子仍是本机管理员。产品阻止 UI 内的未授权暂停和卸载，并能从普通进程退出中恢复，但明确提示管理员仍可通过系统级操作绕过。

## 3. MVP 用户故事

### 家长

- 我可以设置父母密码和一次性恢复码。
- 我可以按星期和 15 分钟粒度设置允许使用时间。
- 我可以按应用设置允许、禁止和临时放行规则。
- 我可以启用或停用图像识别、OCR 关键词识别及对应灵敏度。
- 我可以维护高风险短语、普通敏感词和豁免词。
- 我可以看到组件健康、命中等级、来源应用和处置结果，但默认看不到屏幕截图和 OCR 原文。
- 我可以使用父母密码暂停保护、修改设置或卸载软件。

### 被保护用户

- 我的全部活动显示器会在授权后被独立监控。
- 高风险内容出现时，我先看到即时遮罩和简短原因提示。
- 当 Karma 能可靠确定来源应用时，该应用会被正常关闭；超时后可被终止。
- 当来源不确定时，Karma 只遮罩和告警，不批量结束候选应用。
- 在禁止时间内，被限制的浏览器、播放器、游戏或自定义应用会被关闭并进入冷却期。

## 4. 系统架构

```text
KarmaUI.exe (Tauri + TypeScript，按需启动)
        │ 查询状态 / 带认证的设置变更
        ▼
KarmaService.exe (Windows Service，LocalSystem)
        ├─ 策略快照与时间表
        ├─ 受控应用处置与冷却表
        ├─ Agent 心跳与恢复
        ├─ 审计写入、密钥与配置保护
        └─ 每个登录图形会话启动并验证 Agent
                    │
                    ▼
KarmaAgent.exe (当前用户会话)
        ├─ Windows.Graphics.Capture 多屏采集
        ├─ D3D11 缩放与帧变化检测
        ├─ ONNX 图像分类与 OCR
        ├─ 前台窗口 / 显示器 / PID 归属
        └─ 连续帧状态与结构化观察上报
```

UI、Service、Agent 是三个独立进程。Service 不在 Session 0 截屏；Agent 不直接持有任意终止进程或修改系统策略的能力。共享 Rust 核心以 workspace crates 形式被 Service 和 Agent 复用。

建议仓库结构：

```text
apps/
  karma-agent-windows/
  karma-service-windows/
  karma-ui/
crates/
  karma-domain/       # 稳定领域类型、原因码、版本字段
  karma-policy/       # 时间表、应用规则、风险融合
  karma-ai/           # ONNX 接口、图像模型、OCR 抽象
  karma-storage/      # SQLite、迁移、审计、配置快照
  karma-ipc/          # 消息 schema、认证信封、传输边界
  karma-windows/      # WGC、窗口归属、进程身份等原生适配
models/
  manifest.json       # 模型元数据与哈希，不提交无授权模型
docs/
```

## 5. 屏幕采集与来源归属

### 多屏采集

- 使用 `EnumDisplayMonitors` 获取全部活动 `HMONITOR`。
- 使用 `IGraphicsCaptureItemInterop::CreateForMonitor` 创建独立 WGC 会话。
- 默认每屏每秒送入图像模型 2 帧；资源紧张时降至每秒 1 帧。
- 每个显示器独立维护状态机、采集错误和恢复退避。
- 监听显示器插拔、旋转、DPI、分辨率和 HDR 变化，并在 5 秒内恢复。
- WGC 不可用时记录明确错误；DXGI Desktop Duplication 仅作为后续降级适配，不是第一个开发切片的前置条件。

### 来源归属

Agent 在每次观察时采集：

- 前台窗口句柄、PID、进程启动时间与可执行文件身份。
- 窗口矩形与各显示器的交集面积。
- 全屏、画中画和浏览器多窗口状态。

风险帧优先归属于该显示器上交集面积最大且属于当前前台进程的窗口。发送给 Service 的目标必须包含 PID、进程启动时间、规范化路径、发布者和文件哈希中的可用字段。Service 在处置前重新验证，避免 PID 复用。

## 6. AI 与 OCR 管线

### 统一观察模型

AI 层只生成观察，不直接结束应用：

```rust
RiskObservation {
    monitor_id,
    captured_at,
    image_score,
    image_labels,
    ocr_risk,
    ocr_categories,
    source_identity,
    model_versions,
}
```

`ocr_categories` 只记录类别标识，例如 `explicit_term`、`adult_service`、`exemption_context`；默认不记录识别出的原始文字。

### 图像模型

- 使用 ONNX Runtime。
- 模型清单固定输入尺寸、色彩空间、归一化参数、标签、版本、许可证和 SHA-256。
- MVP 必须同时支持 CPU Provider；GPU Provider 是性能增强而不是正确性前提。
- 模型加载失败时停止图像识别并持续告警，时间表和应用规则继续工作。

### OCR

- 定义 `OcrEngine` 接口，MVP 首选 ONNX Runtime 执行的检测与识别模型，以便后续复用到 macOS。
- OCR 在画面发生显著变化时触发，并限制为每屏每秒最多一次。
- OCR 只处理缩放后的内存帧；结果完成匹配后立即丢弃。
- 词库支持简体中文、繁体中文和英文 Unicode 规范化，后续语言通过版本化词包扩展。
- 规则类型包括：高风险短语、普通敏感词、组合窗口、正则规则和豁免词。
- 词包和模型都必须具备版本、许可证、签名与哈希信息。

### 风险融合

MVP 使用可解释的规则状态机：

```text
image_score >= 0.95
  → 立即进入高风险处置

最近 5 秒至少 3 帧 image_score >= 0.82
  → 进入高风险处置

OCR 命中高风险短语 + image_score >= 0.65，且连续 2 次观察成立
  → 进入高风险处置

OCR 仅命中关键词
  → 提高风险、警告或记录；不得单独强制关闭应用

医疗/教育/新闻豁免上下文
  → 降低 OCR 权重，但不覆盖极高图像分数

连续 10 秒低于恢复阈值
  → 清除显示器风险状态
```

阈值位于签名配置中。每个 Decision 必须提供稳定原因码，UI 可解释“图像高置信度”“连续帧命中”或“图像与文字组合命中”。

## 7. 策略与应用处置

### 决策优先级

```text
紧急故障保护 > 时间段禁止 > 应用黑名单 > 内容高风险
             > 临时放行 > 应用白名单 > 默认允许
```

白名单不默认豁免色情内容；家长必须显式选择“仅豁免时间限制”或“同时豁免内容处置”。

### 处置流程

1. Agent 立即在命中显示器显示本地遮罩。
2. Service 验证来源进程身份和当前策略版本。
3. 向目标顶层窗口发送正常关闭请求。
4. 等待 2 秒并重新验证目标进程。
5. 仍运行且身份一致时终止该目标进程。
6. 将应用加入短期冷却表，阻止立即重启造成循环闪烁。
7. 写入不含原始画面的审计事件。

来源不确定或候选超过一个时，不执行第 3–6 步，只保持短时遮罩并告警。

## 8. Windows Service、自恢复与密码保护

- `KarmaService` 设置为自动启动，并使用 Windows Service Control Manager 的失败恢复策略。
- Service 为每个活动图形会话维护一个经过验证的 Agent；心跳丢失后以指数退避恢复。
- UI 关闭只结束管理界面，不停止 Service 或 Agent。
- 普通用户不具有停止、修改或删除服务的 ACL 权限。
- 安装目录由 `SYSTEM` 和 Administrators 管理，普通用户只读。
- Service 启动时验证 Agent、UI、模型清单和策略快照的签名或哈希。
- 短时间连续崩溃超过阈值后进入受控降级，持续告警而不是无限拉起。

父母密码使用 Argon2id 保存哈希；恢复码只显示一次并只保存哈希。密码验证在 Service 侧完成，UI 不获得密码哈希。连续失败使用指数退避并写入审计事件。

卸载流程同时要求 Windows 管理员授权和父母密码。兼容保护模式下，产品明确说明本机管理员仍能绕过产品自有卸载流程。

## 9. IPC 与权限

- Windows 命名管道使用显式 DACL；不同消息面分别限制 UI、Agent 和 Service 身份。
- 消息带协议版本、消息类型、请求 ID、时间戳和 nonce。
- 初次安装生成设备密钥并由 DPAPI machine scope 封装。
- 策略修改、暂停和卸载请求必须携带短期认证会话证明。
- Service 不暴露“执行任意路径”“删除任意文件”或“终止任意 PID”接口。
- 所有处置请求只能引用近期由 Agent 上报且再次验证的 `SourceIdentity`。
- 未知字段按协议版本规则忽略或拒绝；不允许静默降级安全语义。

## 10. 数据与隐私

- SQLite 使用 WAL 和版本化迁移。
- 配置表、策略表、词库元数据、组件健康和审计事件分离。
- 数据库密钥由 DPAPI 封装；模型、词包和策略更新验证签名。
- 默认不保存帧、OCR 原文、完整 URL、键盘输入或窗口正文。
- 审计日志保存时间、用户 SID、显示器、应用身份、风险等级、类别、原因码、模型版本和处置结果。
- 日志保留期可配置，默认 30 天；清理动作本身进入审计。

## 11. 故障行为

| 故障 | MVP 行为 |
|---|---|
| 图像模型失败 | 停止图像识别，保留 OCR、时间表和应用规则，持续告警 |
| OCR 模型失败 | 停止 OCR，保留图像识别，持续告警 |
| 单屏采集失败 | 仅重建该屏采集会话，其他屏继续运行 |
| Agent 崩溃 | Service 限速恢复；多次失败后显示高优先级健康告警 |
| Service 崩溃 | SCM 恢复 Service；Agent 进入遮罩可用但不处置的降级状态 |
| 数据库损坏 | 加载最后签名策略快照并进入只读模式 |
| IPC 认证失败 | 拒绝请求并记录安全事件 |
| 无法确定来源应用 | 仅遮罩和告警，不结束多个候选进程 |
| 磁盘空间不足 | 停止新增普通审计，保留轮转后的安全事件空间 |

## 12. 开发切片

### Slice 1：可测试领域核心

- Rust workspace、领域类型和版本化 schema。
- 时间表、应用规则、连续帧状态机与 OCR/图像风险融合。
- 内存审计接口和 fake clock/fake AI 测试替身。

### Slice 2：Windows Agent 采集闭环

- 单屏 WGC 采集、帧节流和前台窗口归属。
- ONNX 模型清单与图像推理接口。
- OCR 接口、词库匹配和内存结果清理。
- 使用离线测试素材验证决策，不在测试仓库保存违法或不必要的露骨素材。

### Slice 3：多屏与 Service

- 多屏热插拔、独立状态机。
- Service 安装、命名管道、Agent 心跳和 SCM 恢复。
- 正常关闭、身份复核、超时终止与冷却。

### Slice 4：管理 UI 与持久化

- 设置向导、密码、恢复码、时间表和应用规则。
- OCR 词库类别管理、阈值设置和隐私说明。
- SQLite、DPAPI、审计浏览和数据导出。

### Slice 5：安装与强化验证

- MSI、代码签名、目录与服务 ACL。
- 标准用户和管理员兼容模式提示。
- 睡眠唤醒、多用户、三屏、VPN/安全软件兼容及性能测试。

WFP、WDAC/AppLocker、内核驱动和 macOS 适配不属于 Windows MVP 的完成条件，分别进入后续规格。

## 13. 验收标准

- Windows 10 22H2 与 Windows 11 上可安装并完成明确授权。
- 全部活动显示器独立采集；插拔后 5 秒内恢复。
- 默认每屏 2 FPS，繁忙时最低 1 FPS；无风险空闲 CPU 平均低于 3% 的目标在指定基准机上测量。
- 测试集中高置信内容出现后 3 秒内产生处置 Decision。
- OCR 支持中英文规范化、短语、正则和豁免词；OCR 单独命中不会强制关闭应用。
- 禁止时间内，已识别应用在启动后 500ms 内收到阻止或处置 Decision。
- 来源可靠时遵循“遮罩、正常关闭、复核、终止、冷却”顺序；来源不可靠时不批量终止。
- 标准用户不能通过关闭 UI、任务管理器普通操作或直接运行卸载器停止保护。
- Agent 异常退出后 5 秒内恢复，且反复失败不会形成无限重启风暴。
- 连续运行 30 天默认不产生原始屏幕文件或 OCR 原文记录。
- 所有管理操作和处置均生成可验证的结构化审计事件。
- 管理员兼容模式清楚标注可绕过边界，不宣传绝对不可卸载。

## 14. 测试策略

- 领域核心采用单元测试和属性测试，fake clock 覆盖跨午夜、时区变化和冷却期。
- 风险状态机使用表驱动测试覆盖阈值边界、连续帧、OCR 组合和豁免上下文。
- IPC 使用畸形消息、重放、越权角色和版本不兼容测试。
- Storage 使用临时数据库验证迁移、中断恢复和损坏回退。
- Windows 适配使用集成测试验证窗口归属、PID 复用、正常关闭和多用户会话。
- UI 使用组件测试覆盖密码流程、危险操作确认和能力降级提示。
- 端到端测试覆盖双屏/三屏、DPI、旋转、HDR、睡眠、锁屏和快速用户切换。
- 性能基准分别记录 CPU-only、集显和独显配置，报告每屏帧率、P95 推理时延和内存。

## 15. 待后续规格解决的问题

- 生产图像模型和 OCR 模型的最终许可证、偏差评估与更新渠道。
- WFP 按应用联网时间控制及与 VPN/代理共存。
- WDAC/AppLocker 家庭强化模板。
- 是否申请 Windows 反恶意软件生态资格；不作为当前产品依赖。
- macOS ScreenCaptureKit、System Extension 和 Network Extension 适配。
