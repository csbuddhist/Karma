## 3. 单显示器功能

1. 以普通交互用户启动 `karma-agent-windows`，确认状态为 `ready` 且工作器保持运行。
2. 依次展示静态桌面、快速滚动页面和 SDR 视频至少 5 分钟。
3. 确认帧处理计数持续增加，进程不产生截图、临时图片或像素日志。
4. 确认正常 GPU 上未持续增加 CPU fallback 计数；若发生降级，记录适配器、驱动和稳定错误类别。
5. 确认空推理消费者不会触发应用关闭、网络访问或内容上传。

通过标准：持续收到帧，无崩溃、无非预期磁盘图像、无无界内存增长，SDR BGRA 颜色在后续诊断消费者中正确。

## 4. 多显示器与负载

1. 连接两台或三台显示器，使用不同分辨率和 DPI 缩放。
2. 每台显示器同时播放或滚动不同内容至少 15 分钟。
3. 确认每台显示器具有独立工作器与计数；一个显示器停止或失败不应阻塞其他显示器。
4. 记录空闲 5 分钟和视频负载 15 分钟的 CPU、GPU、私有工作集与句柄数。
5. 确认处理落后时只替换旧帧，不出现随时间增长的队列或内存曲线。

通过标准：各显示器持续独立处理；内存达到稳定平台；无 D3D11 immediate-context 并发告警或设备移除错误。

## 5. 尺寸和生命周期

逐项执行并记录工作器最终状态和恢复行为：

- 更改分辨率。
- 更改 DPI 缩放。
- 横屏/竖屏旋转。
- 拔出并重新连接外接显示器。
- 睡眠并唤醒。
- 锁屏并解锁。
- 启动 UAC 安全桌面。
- 结束 Agent。

当前切片的预期是尺寸变化进入 `RecreateRequired`、目标关闭进入 `TargetClosed` 并释放会话；热插拔自动重建尚未实现，因此不得把“自动恢复”标为通过。

## 6. GPU 与 CPU 降级

1. 在支持 D3D11 Video Processor 的硬件上确认 GPU resize 路径工作。
2. 在 WARP、远程桌面或明确不支持视频处理器的环境中确认进入 CPU fallback，而不是崩溃。
3. 确认 fallback 的全尺寸瞬时缓冲在缩放完成后释放并零化。
4. 使用超过限制的合成纹理测试时，确认 16K 边长或 256 MiB 上限拒绝映射。
5. 模拟 device removal 后确认工作器进入失败状态且不形成无限重试循环。

## 7. 停止与资源释放

1. 正常请求停止所有工作器。
2. 确认通知通道唤醒阻塞线程，线程可 join，WGC 事件 token 被移除。
3. 确认 capture session、FramePool、捕获帧、staging texture 和视频处理器资源释放。
4. 重复启动/停止 20 次，比较私有工作集、句柄数和 D3D 调试层输出。

通过标准：没有迟到帧残留、死锁、线程泄漏、COM apartment 错误或稳定增长的 GPU/系统句柄。
