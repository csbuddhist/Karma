# Windows ONNX 图像推理验收

本清单用于 Windows 10 22H2 和 Windows 11 真机。macOS 单元测试及 Windows
交叉编译不能证明实际推理性能、驱动兼容性或内容识别准确率。

## 准备

1. 按 [模型资产说明](model-assets.md) 导出固定版本模型。
2. 将 `model.onnx`、`manifest.json` 和模型 `LICENSE` 放入只读安装资产目录。
3. 将 `KARMA_IMAGE_MODEL_MANIFEST` 设为 `manifest.json` 的绝对路径。
4. 在允许屏幕捕获的交互式用户会话中启动 `KarmaAgent.exe`。

缺少、损坏或合同不匹配的模型必须在显示器枚举前失败，并只输出稳定错误类型。运行中
日志只能包含显示器标识、推理次数、失败次数和延迟等健康数据，不得包含像素、分类
分数、标签概率、窗口正文或完整 URL。

## 功能验证

- 单屏和至少双屏都能分别建立 WGC 与 ONNX Runtime CPU 会话。
- 每个显示器的图像推理频率不超过 2 FPS；一个显示器繁忙不阻塞其他显示器。
- 静态画面、视频播放、窗口移动、分辨率变化和显示器断开不会泄漏帧缓冲。
- 模型文件长度或 SHA-256 被更改后，Agent 拒绝启动图像推理。
- 连续运行中的单次推理失败只增加失败计数，不终止帧工作器。
- 同一显示器连续 3 次推理失败后健康状态变为 `unavailable`；后续成功推理恢复状态。
- 进程退出后模型会话、D3D11 资源和已准备帧均被释放。

## 性能记录

分别在单屏和双屏场景持续运行至少 30 分钟，记录：

- 每显示器实际采集 FPS 与推理 FPS；
- ONNX 推理延迟 P50、P95 和最大值；
- Agent CPU、专用工作集与提交内存；
- 推理成功数、失败数和丢弃的过期帧数；
- 视频播放期间的系统响应与电池/温度变化。

验收报告必须注明 CPU 型号、内存、Windows 版本、显示器分辨率/缩放、模型 SHA-256
以及是否使用 GPU 缩放降级路径。

## 准确率边界

使用经授权的内部测试集评估正常、绘画、性感、裸体、色情和困难负样本，按类别记录
精确率、召回率、混淆矩阵及阈值曲线。测试素材不得提交到仓库或写入运行日志。完成
该评估之前，不得宣称模型达到产品准确率；本阶段也不包含 OCR、连续帧决策或关闭
来源应用的端到端准确率。
